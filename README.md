# Iris Flower Classification

A production-grade ML pipeline that classifies iris flower species from morphological measurements using a Support Vector Machine (SVM), wrapped in a leak-free scikit-learn `Pipeline` with model persistence and CLI-based inference.

## Overview

Given four physical measurements of an iris flower — sepal length, sepal width, petal length, and petal width — this classifier predicts which of the three species it belongs to:

| Species | Characteristics |
|---------|----------------|
| *Iris-setosa* | Small petals, clearly separable |
| *Iris-versicolor* | Medium petals, partial overlap with virginica |
| *Iris-virginica* | Large petals, partial overlap with versicolor |

### Performance

| Metric | Value |
|--------|-------|
| 5-Fold Stratified CV Accuracy | **96.67% (+/- 5.16%)** |
| Holdout Test Set (20%) | **100% precision, recall, F1** |
| Confidence Estimation | Enabled via `predict_proba` |

## Architecture

```
                  ┌─────────────────────────────────────┐
                  │          sklearn.Pipeline            │
                  │                                     │
  Input (4 floats)│  ┌──────────────┐  ┌─────────────┐ │  Output
 ─────────────────┤  │ StandardScaler│──│  Linear SVC │ ├──────────────
                  │  │ (zero-mean,  │  │ (C=1.0,     │ │  Species +
                  │  │  unit-var)   │  │  probability)│ │  Confidence %
                  │  └──────────────┘  └─────────────┘ │
                  └─────────────────────────────────────┘
```

The scaler and classifier are bundled into a single `Pipeline` object. This design guarantees that during cross-validation, the scaler is fitted **only** on each training fold — preventing data leakage that would otherwise inflate accuracy metrics.

## Quick Start

### Prerequisites

- Python 3.10+
- pip

### Installation

```bash
git clone https://github.com/pnitishkumar/Petal-Detection.git
cd Petal-Detection
pip install pandas numpy scikit-learn joblib
```

### Usage

The script supports three execution modes:

```bash
# 1. Train the model (runs EDA, cross-validation, holdout evaluation, saves artifact)
python Petal_Detection.py --train

# 2. Single prediction from the command line
python Petal_Detection.py --predict 5.1 3.5 1.4 0.2

# 3. Interactive mode (launches a prediction REPL; auto-trains if no model exists)
python Petal_Detection.py
```

## Design Decisions

### Why `Pipeline` instead of separate `StandardScaler` + `SVC`?

Fitting the scaler on the full dataset before cross-validation causes **data leakage** — the test fold's mean and standard deviation influence the scaler, artificially inflating accuracy. Wrapping both steps in a `Pipeline` ensures the scaler sees only training data in each fold.

### Why retrain on 100% of data after evaluation?

Cross-validation and holdout evaluation establish confidence in the model's quality. Once validated, the production model should leverage every available sample for maximum predictive power. The evaluation metrics from the holdout split serve as the documented performance baseline.

### Why `joblib` persistence?

Training and inference are decoupled. `--train` produces a versioned artifact (`iris_pipeline.joblib`); subsequent `--predict` or interactive runs load this artifact instantly without retraining. `joblib` is preferred over `pickle` for efficient serialization of numpy-heavy objects like SVM support vectors.

### Why no `LabelEncoder`?

scikit-learn's `SVC` natively accepts and returns string labels. Adding a `LabelEncoder` introduces unnecessary state that must be managed and serialized separately, with no benefit for this use case.

### Input Validation

Feature values are checked against biologically plausible bounds (derived from the dataset's observed ranges with margin). This prevents the model from silently returning predictions for physically impossible inputs like negative petal widths.

## Dataset

The [Iris dataset](https://archive.ics.uci.edu/ml/datasets/iris) (Fisher, 1936) contains 150 samples across 3 species (50 each):

| Feature | Min | Max | Unit |
|---------|-----|-----|------|
| Sepal Length | 4.3 | 7.9 | cm |
| Sepal Width | 2.0 | 4.4 | cm |
| Petal Length | 1.0 | 6.9 | cm |
| Petal Width | 0.1 | 2.5 | cm |

Source: [UCI Machine Learning Repository](https://archive.ics.uci.edu/ml/datasets/iris)
